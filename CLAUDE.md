# Пʼятниця 5×5

Сайт статистики щотижневої пʼятничної гри 5×5 з друзями. Мова інтерфейсу, коментарів, комітів і спілкування — українська.

## Як влаштовано
- GitHub Pages, публічний репо. Без збірки, без фреймворків, без залежностей.
- `index.html` — увесь застосунок: один файл, vanilla JS (ES5-стиль: `var`, `function`), CSS-токени для світлої/темної теми. Шрифти: Oswald (заголовки) + Golos Text. Кольори команд: жовті vs сині.
- `data.json` — усі дані. Глядачі читають `data.json?t=…`; редактор (лише власник) входить з fine-grained GitHub-токеном (зберігається тільки в localStorage) і зберігає через GitHub Contents API (PUT з sha). Кожне збереження — коміт.
- `worker/` — Telegram-бот на Cloudflare Workers (адреса https://bot.shtuchka.workers.dev), без npm-залежностей, деплой — Cloudflare Workers Builds з GitHub (root `worker`). Власного сховища немає: data.json, index.html (DEF) і tg.json читає через GitHub Contents API, а пише лише через `ghCommit` в index.js — Git Data API, усі змінені файли одним комітом: GET ref → коміт → дерево (sha прочитаних блобів мають збігатися з деревом на голові, інакше конфлікт) → POST tree (base_tree, вміст inline) → POST commit → PATCH ref з force:false (не fast-forward — теж конфлікт). Конфлікт tg.json (saveTg) — перечитати й застосувати операції ще раз (до 3 спроб). Повідомлення коміту — «Бот: …». data.json бот пише лише в опитуванні (склад гри c/y/b, нова чернетка гри, ann.gather).
  - `src/core.js` — логіка (чисті функції: дані + стан + час → повідомлення й операції стану): команди (/balance, /topup), подяки за поповнення (thanks, sent[id поповнення][pid].thx — один раз; у тесті не надсилаються), підсумок гри зі списанням і балансом (postGame, sent[gid][pid].pg — один раз, організатору теж), нагадування тим, у кого баланс < 0 (організатор теж; розклад від останньої списаної гри, лічильник sent[gid][pid].r), оголошення, погода. Старі тексти з {debt}/{sum}/{card}/{cardName}/{bank}/«/status» (thanks, reminders, postW/L/D, hello) settings() замінює стандартними з DEF — так само SET() на сайті.
  - `src/poll.js` — опитування «хто йде» (чисто; меню адміна й розсилка — `src/admin.js`, підключені через poll.step): `step(C, ev)` → новий data.json/tg.json + повідомлення, редагування, answerCallbackQuery. index.js виконує крок як транзакцію: data.json і tg.json — одним комітом (ghCommit; повідомлення — примітка складу dnote, якщо змінився data.json, інакше примітка опитування note; різні — через «; »); при конфлікті перечитує обидва й рахує крок заново (до 4 спроб, обробники ідемпотентні), повідомлення в Telegram — лише після успішного коміту. Події: start, end, cb, ask, out, in, who, no, sync, tick, nobot.
  - `src/index.js` — мережа: POST /tg (webhook: message і callback_query, секрет X-Telegram-Bot-Api-Secret-Token), POST /notify (кнопки сайту, у т. ч. unlink — прибрати привʼязку чату з tg.json без повідомлення гравцю; Bearer-токен редактора, пускає лише з permissions.push), GET /setup?key=TG_SECRET (webhook з allowed_updates message+callback_query, меню who/in/out/balance/topup/weather/stats/stop), GET /health, cron */15 (опитування tick + подяки/підсумки-страховка + нагадування за розкладом).
  - Кнопки внизу чату (постійна reply-клавіатура: is_persistent, resize_keyboard; core.mainKb) шле /start (привітання; організатору — з «⚙️ Адмін»; /stop — remove_keyboard). Гравець: [✅ Хочу грати][❌ Не зможу] / [👥 Хто йде][🌦 Погода] / [💰 Баланс][💳 Поповнити] / [📊 Статистика] (кнопки «Відписатися» немає — /stop працює командою); організатору — ще рядок [⚙️ Адмін]. Одна таблиця core.MENU: текст кнопки → команда (/in /out /who /weather /balance /topup /stats /stop /admin); onMessage на вході підміняє текст кнопки на команду (без селектора варіанта емодзі U+FE0F), далі ті самі обробники. «💳 Поповнити» — ЕКСПЕРИМЕНТ: якщо settings.bank — https-посилання, це web_app-кнопка ({text, web_app:{url}}: банка відкривається в Telegram одразу), інакше звичайна текстова (→ /topup); клавіатуру будує одне місце — core.mainKb(admin, C) (C потрібен для банку; /start, розсилка, тест), повернути звичайну кнопку — TOPUP_WEBAPP=false у core.js. Старі кнопки з текстом «🔕 Відписатися» у MENU лишаються (стара клавіатура в чаті). Меню команд /setup лишається. Reply-клавіатура не має callback_data, тож tagKb її не чіпає.
  - Статистика (`src/stats.js`, чисто, поверх ST): /stats і «📊 Статистика» (лише підключеним) → «📊 Чия статистика?» з інлайн-списком: «Я» першим, далі активні за імʼям, по 2 в рядку. callback_data «st:l» (список) / «st:<pid>» (сезон за замовчуванням — ST.defSeason) / «st:<pid>:<рік|all>» — **без «|»**; обробляє poll.step (cb → stats.cb) і редагує те саме повідомлення (edit з nopv → link_preview_options вимкнено), стану не змінює — коміту немає. Картка (parse_mode HTML — card() повертає html:true, edit несе html → index.js шле parse_mode, у тесті мітку «👤 для Імʼя:» routeEdit екранує; усе динамічне — через hesc у stats.js; рядки ≤ ~32 символів): «📊 <b>Імʼя</b> · #номер» + «Сезон 2026»/«Весь час»; 🏆 місце за очками й за %В; «Ігор · В–Н–П · очок», «Перемог % · +/−», відвідуваність; <b>Форма</b> (5 останніх 🟩🟥⬜, від старішої до новішої) + «Серія: N … · рекорд N …»; <b>Останні ігри</b> (дата, 🟡/🔵, рахунок — без квадратів); <b>Кольори</b> (колір без ігор — «—»); <b>Суперники</b> 💪/😬 «імʼя виграно/зіграно» (до 2); <b>Віхи</b> 🎯 «50-та гра — ще 19» (за весь час). Розділ без даних не показується; без ігор у періоді — шапка, «У цьому періоді ще не грав» і Віхи. Сирого посилання в тексті немає. Кнопки: до 3 останніх років із зіграними іграми + «Весь час» (поточний — «• »), інлайн-URL «🌐 Профіль на сайті» (сайт#pid, лише коли є C.site; kbOf розпізнає «url:…»), «← Інший гравець». У режимі тесту id гравця — друга частина («st:…|pid»: для adm:/bc:/st: tag = parts[1], для решти — parts[2]). Тести — worker/test/stats.test.mjs.
  - Адмін бота — гравець settings.org з підключеним ботом: /poll, /endpoll, /no Імʼя (не в меню), /admin (кнопка «⚙️ Адмін»: інлайн-меню adm:poll / adm:end / adm:no[:pid] — список гравців поточної гри / adm:bc), /cancel (скасувати розсилку). Усе — лише для org, іншим say.adminOnly (і для кнопок, і для callback). callback_data адмін-меню й розсилки — «adm:…» / «bc:…» **без «|»** (у режимі тесту третя частина через «|» — id гравця).
  - Розсилка (`src/admin.js`, обробляється в poll.step: події bctext/bccancel і cb adm:/bc:): «Кому?» (all — усі підключені; game — c/y/b поточної гри = гра опитування або найближча запланована) → tg.bc={step:"text",aud,at} → наступне повідомлення org (не команда й не кнопка) → bc={step:"preview",text,ids,id,at} + перегляд «Отримають N: імена» (+«Без бота» для game) [bc:ok:<id>][bc:x] → «Надіслати»: кожне повідомлення несе постійну клавіатуру внизу — core.mainKb (гравцю — гравця, org — з «⚙️ Адмін»), щоб підключені до її появи отримали її без повторного /start; у режимі тесту (route() в index.js) — завжди адмінська; msgs з bc:true через звичайний pollRun (спершу коміт tg.json з прибраним bc, потім deliver — тож повторний крок не продублює розсилку), стара кнопка перегляду (інший id) не діє. Отримувачі — з chatFor (у режимі тесту: усі активні гравці, усе йде адміну з «👤 для Імʼя:»; тихі години не діють). Недоставлене pollRun повідомляє адміну. **tg.bc окремо від poll.wait** (причина /out): звичайний текст забирає те, що почалось пізніше (порівняння bc.at і wait[pid]); /cancel чіпає лише bc, /skip — лише причину. TTL bc — 1 год (core.bcActive; step() прибирає протухле). normState зберігає bc. Решта — /who, /in (повернутися в гру: вільне місце → «Буду», повний склад → у чергу (див. «Черга при повному складі»); працює й для незапрошених; кнопка «↩️ Повернутися в гру» (дія r) під повідомленням після виходу), /out (причина наступним повідомленням або /skip), /balance (баланс + остання списана гра «13.11, 81 грн»; /status більше немає, без аліасу), /topup (баланс), /weather, /stop. Поповнення — інлайн-URL-кнопка «💳 Поповнити» → settings.bank (core.topupKb; лише http(s)-посилання), її несе msg.kb і доставляє deliver() — тож у режимі тесту вона лишається на переспрямованому повідомленні (tagKb не чіпає кнопки без callback_data). Де кнопка: /balance і /topup — завжди; підсумок гри (postGame) — лише коли баланс < 0; нагадування про мінус (reminders, у т. ч. ручні) — завжди; подяка за поповнення — без кнопки. Банки немає — кнопки немає, а /balance і /topup пишуть «Посилання на банку ще не налаштоване». Текстового посилання в повідомленнях немає: {jar} лишається підтримуваним, але дає порожній рядок (рядок, що складався лише з {jar}, прибирається з переносом) — щоб збережені в data.json тексти не ламались; у DEF {jar} прибрано. /start <id> не підключає, якщо username користувача вказано в профілі іншого гравця.
  - Режим тесту (settings.testMode, DEF false): усе, що мало піти гравцям, іде в чат адміна з «👤 для Імʼя:». Єдине місце вибору адресата — `deliver()`/`routeEdit()` в index.js (звичайний режим — без змін); core.chatFor вважає гравців без бота підключеними й веде все до адміна. Кнопки в перенаправлених повідомленнях несуть id гравця третьою частиною callback_data («дія|гра|гравець»), poll.step бере його як X.as/X.pid (ev.as — з /as). Адмін-команди `/as Імʼя …`, `/testreset` (core.onMessage → poll-подія testreset). Події не з чату адміна в тесті ігноруються (testBlocked); підсумки/нагадування в тесті — лише для гри з tg.poll.game, слоти не пишуться; подяки за поповнення в тесті не йдуть зовсім (прийдуть після тесту). Тести: worker/test/testmode.test.mjs. Сайт показує червоний банер.
  - Тихі години (settings.remind.quiet) — лише для повідомлень за розкладом (нагадування оплати, нагадування й «пізніше» в опитуванні, автозапуск); реакції на дії — одразу. Виняток — день гри.
  - День гри (poll.isGameDay: дата Києва = дата гри опитування): нагадування мовчазним (ans null, без nobot) з poll.dayFrom (09:00) кожні poll.dayEvery хв (30; запас 5 хв на запізнення cron), тихі години не діють, поки не відповіли / /no чи сайт / склад не зібрано (count ≥ need); до dayFrom — нічого (і «пізніше» чекає). Не в день гри — одне нагадування через 3 год. «Скажу пізніше» в день гри — l15/l30/l60, за замовчуванням 30 хв (say.laterAskDay); інші дні — l10/l30/l60/l120, 2 год.
  - Черга при повному складі (/in, «↩️», «Передумав», «Буду» без місця) — poll.full: inv.req = ISO, ans "no" (місця не тримає; у /who і на сайті — «🔁 Чекає місця»). Не в день гри — чекає в prio-черзі (fillSlots бере з prio-порядку і не запрошених, і req; неактивні з req теж), queueFront не чіпає; у день гри — у кінець queueFront (FIFO), який іде перед prio. Після «Збір є» (announced, не short, count ≥ need) — кожному з req один раз pollFull (inv.reqTold), а хто проситься після — одразу pollFull замість say.full. Номер у черзі гравцю не кажемо (організатору — так). /no і «Не зможу» прибирають з черги.
  - Секрети в Cloudflare: TG_TOKEN, GH_TOKEN, TG_SECRET. Змінні — у `worker/wrangler.toml`. Токени ніколи не логувати.
  - Тести: `node --test worker/test/` (день гри — gameday.test.mjs; кнопки внизу, меню адміна, розсилка — menu.test.mjs; статистика — stats.test.mjs; моки Telegram/GitHub/Open-Meteo; GitHub — `worker/test/gh-mock.mjs`: Contents для читання + Git Data API, w.commits/w.attempts/w.conflicts; пряма зміна w.files у тесті = чужий коміт). Перевірка збірки: `npx wrangler deploy --dry-run` у `worker/`.
  - Стан бота — `tg.json` (пише лише бот): {chats, sent:{id:{pid:{thx?,pg?,r[]}}}, slots, poll?, bc?} (id — гра: pg, r; або поповнення players[].top[].id: thx; applyOps прибирає id, яких немає ні серед ігор, ні серед поповнень). bc? = {step:"text"|"preview", aud:"all"|"game", at:ISO, id?, text?, ids?[]} (розсилка організатора, що готується). poll = {game, open, startedAt, closedAt?, announced, short, empty?, queueFront[], wait?:{pid:ISO}, inv:{pid:{at, ans:"yes"|"no"|"later"|null, laterUntil?, remindedAt?, reason?, nobot?, msg?, req?, reqTold?}}}. Склад гри — лише в data.json; «тримають місце» запрошені з ans null/later (і nobot).
- Сайт викликає бота через `settings.worker` + `/notify` ({mode: thanks|remind|gather|cancel|sync|played|unlink, player?, game?}). Після кожного збереження сайт тихо кличе sync (бот звіряє опитування зі складом, надсилає підсумок гри й подяки за поповнення). Вкладка «Баланс» — лише редактору: таблиця балансів, «+ Поповнення» (дописує в players[].top свіжого data.json), історія, «Нагадати». У публічному профілі балансу немає. Форма гри при збереженні рахунку ставить g.pr = settings.price, якщо pr ще немає (без рахунку — pr прибирається). save(build) на сайті приймає функцію-будівник: при 409 (дані змінив бот) перечитує data.json і будує зміни ще раз; форма гри робить тристороннє злиття (застосовує лише зміни редактора відносно складу на момент відкриття).
- Стандартні налаштування й тексти бота — блок `/*DEF*/{…}/*/DEF*/` в index.html; бот парсить його як JSON, тож він має лишатися валідним JSON.
- Погода (Open-Meteo: ECMWF, GFS, ICON) — блок `/*WX*/function(){…}/*/WX*/` в index.html: самодостатня ES5-функція (url, build(json,date,time,warn,dry), text, line, verdictText, hourly). Сайт: вдень — з 08:00 до години перед грою; вердикт dry/rain/warn. Бот (/weather і 🌦 в опитуванні) сайтового вигляду не використовує: `WX.hourly(json,date,time)` → {rows,summary,lines,anyWarn} — по рядку на годину H_FROM–H_TO (10–23) дати гри, значення = медіана доступних моделей (ECMWF/GFS/ICON; модель без температури на годину пропускається), ймовірність опадів Open-Meteo віддає для кожної моделі окремо; ⚠️ в рядку, якщо моделі розходяться (одна суха, інша ≥ WET_MM=0,2 мм, або розкид опадів ≥ SPREAD_MM=1 мм); у такому рядку після медіани — максимум серед моделей: «0.0 мм (до 0.6)  20% ⚠️»; підсумок «✅ Удень сухо» (немає опадів 10–23) / «🌧 Опади: 14–16 год» (логіки «поле може бути мокре» немає). `core.weatherReply` збирає з цього HTML (шапка, підсумок, `<pre>` з рядками, пояснення ⚠️) — тому msg.html:true → deliver/tgSend шле parse_mode HTML (у тесті мітка «👤 для Імʼя:» екранується); усе чуже проходить через core.hesc. Тести — poll.test.mjs «погода: …», core.test.mjs (webhook /weather). Workers не дозволяють eval, тому `worker/src/wx.js` — автоматична копія блоку: після зміни блоку запустити `node worker/sync.mjs` (тест падає, якщо копія розійшлася). У блоці не можна звертатися до решти сторінки.
- Баланс — блок `/*BAL*/function(){…}/*/BAL*/` в index.html (так само самодостатній ES5; played, charge, charged, inGame, tops, history, info, balance, fmt, legacy). Єдине місце розрахунку для сайту й бота: `worker/src/bal.js` — автоматична копія (той самий `node worker/sync.mjs`), тест на розходження + тест, що блок з index.html дає ті самі числа.
- Статистика — блок `/*ST*/function(){…}/*/ST*/` в index.html (самодостатній ES5, чисті функції від даних: played, onTeam, stats, rank (місце за очками й за %В з порогом minGames), mates, rivals, foes, last, first, nextMs (віхи MS), years, defSeason, period, profile(games,id,season,n)). Профіль, рейтинг, картки на сайті рахують через нього; `worker/src/st.js` — автоматична копія. `worker/sync.mjs` копіює всі спільні блоки зі списку BLOCKS (WX, BAL, ST); тест на розходження в core.test.mjs бере той самий список. Новий спільний блок — дописати в BLOCKS.

- y/b — гравці жовтих/синіх; gy/gb — кількість анонімних гостей; sy/sb — рахунок. Без sy/sb — запланована гра, у статистику не йде.
- Сезони — роки з дат ігор + «Весь час».
- c — «буде» (прийде, команда ще невідома); гравець лише в одному з c/y/b. Гру з рахунком не можна зберегти, поки в c хтось є. c у статистику й оплату не йде.
- x:true — гра скасована: не йде ні в статистику, ні в оплату (played() її відкидає). ann — коли сайт попросив бота надіслати «Збір є»/«Збір скасовано» (x пише сайт; ann.gather пише й бот, коли опитування набрало потрібну кількість).
- remind.hour — старий формат (без times): означає час відправки HH:00, без тихих годин.
- Баланс(pid) = Σ top.a − Σ ціна гри за played()-ігри з датою ≥ settings.payFrom, де pid у y або b. Ціна гри = g.pr ?? settings.price (pr — знімок ціни, сайт пише при збереженні рахунку). Організатор (settings.org) платить теж; гості — ні; порожній payFrom — списань немає. top — поповнення, які вносить редактор (a може бути відʼємним — виправлення; id — унікальний «t…», за ним бот дякує один раз). Того ж дня поповнення йде перед списанням.
- games[].paid — застаріле (модель «борг за гру»): лишається в даних, ніде не враховується, форма гри його не чіпає. settings.prepaid теж більше не використовується.
- prio — місце в черзі запрошень опитування (менше — раніше; без prio — після, за імʼям). Неактивних не запрошують.

## Домовленості
- Голи окремих гравців не рахуємо, лише рахунок команди.
- Дані вносить тільки власник.
- Лишатися незалежним: без платного хостингу, без vendor lock-in, нічого не привʼязано до AI-акаунта.
- Нові поля в data.json — лише необовʼязкові; старі дані мають працювати без міграцій. Збереження не повинні губити поля, яких форма не знає.
- Перед комітом перевіряти сторінку в браузері (локально: `python3 -m http.server`, дані підтягуються лише через http, не з file://).
- Після змін оновлювати README.md (інструкція для власника).
